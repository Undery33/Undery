## 주소와 설정을 배포하는 서비스

DHCP(Dynamic Host Configuration Protocol)는 클라이언트에 IP 주소와 네트워크 설정을 제공하는 프로토콜입니다. 이 문서는 **IPv4의 최초 임대 과정**을 다룹니다. 서버는 서브넷별 주소 풀과 임대 시간을 관리하며 서브넷 마스크, 기본 게이트웨이, DNS 서버 같은 설정도 전달합니다.

주소 풀은 할당 후보 주소의 모음입니다. **임대**(lease)는 특정 클라이언트가 주소를 사용할 수 있는 기간입니다. **예약**(reservation)은 식별자가 일치하는 클라이언트에 정해진 주소를 제공하는 설정입니다. 예약을 만들었다고 클라이언트가 곧바로 주소를 받은 것은 아닙니다.

## DORA의 네 메시지

- **Discover**: 주소가 없는 클라이언트가 서버를 찾습니다.
- **Offer**: 서버가 주소와 설정을 제안합니다. 아직 확정된 임대가 아닙니다.
- **Request**: 클라이언트가 선택한 서버와 요청할 주소를 알립니다.
- **ACK**: 선택된 서버가 임대를 확정하고 설정을 응답합니다.

Offer와 ACK 사이에는 클라이언트의 선택이 있습니다. 서버는 제안한 주소를 임시로 사용 불가 상태에 둘 수 있지만 이것을 확정된 임대와 혼동하면 안 됩니다. ACK를 받은 클라이언트도 실제 주소 충돌 여부를 확인해야 합니다. 여러 서버의 제안, 재전송, 갱신은 아래 최초 할당 모형에서 생략했습니다.

## 주소 풀과 예약을 직접 조작하기

예제 풀은 `192.168.10.100~103` 네 주소입니다. 클라이언트 A의 Discover부터 ACK까지 진행하며 언제 임대 목록에 나타나는지 확인합니다. 다른 클라이언트를 선택하면 이미 임대한 주소를 피해서 제안합니다.

초기화한 뒤 A의 `.103` 예약을 켜면 A는 예약 주소를 제안받습니다. 다른 클라이언트는 그 주소를 사용할 수 없습니다. `고갈 예시`에서는 네 주소를 이미 사용 중이므로 E에게 Offer가 오지 않습니다. 가상 시간을 120초 진행하면 임대가 만료되어 다시 할당할 수 있습니다.

## 운영 시 확인할 사항

- 고정으로 설정한 장비 주소와 동적 풀, 예약 주소가 충돌하지 않도록 관리합니다.
- 남은 주소 수와 임대 기록을 확인합니다. 풀 고갈과 서버에 메시지가 도착하지 않는 문제를 구분합니다.
- 다른 서브넷의 클라이언트는 DHCP 릴레이와 경로를 확인합니다. 서버 UDP 67번, 클라이언트 UDP 68번 통신도 점검합니다.
- 실제 클라이언트는 임대 만료 전에 갱신을 시도합니다. 실습의 120초와 자동 갱신 생략은 상태 비교를 위한 설정입니다.

이 실습은 브라우저 안의 상태 모형입니다. 실제 DHCP 서버를 실행하거나 기기의 주소를 바꾸지 않습니다. DHCPv6와 IPv6의 주소 구성은 별도 기술로 다룹니다.
