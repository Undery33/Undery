# Markdown 글 작성

기술 글은 `content/computer/`의 `.md` 파일로 관리합니다. 현재 웹 관리자 작성 화면은 없으며, 파일 수정 후 검사·새 빌드가 필요합니다.

## 파일과 메타데이터

파일명은 `my-first-post.md`처럼 영문 소문자·숫자와 단어 사이 하이픈을 사용합니다. 파일명이 `/computer/my-first-post`의 slug가 됩니다. 공백, 한글 파일명, 밑줄, 경로 구분자는 허용하지 않습니다.

```markdown
---
title: "첫 번째 기술 기록"
description: "목록에 보여 줄 짧은 요약입니다."
publishedAt: "2026-11-06"
tags: ["개발", "Markdown"]
draft: true
example: false
---

## 기록할 내용

본문을 작성합니다.
```

- `title`, `description`: 비어 있지 않은 문자열, 필수.
- `publishedAt`: 따옴표로 감싼 유효한 `YYYY-MM-DD` 날짜, 필수.
- `tags`: 비어 있지 않은 문자열을 하나 이상 포함한 배열, 필수. 앞뒤 공백과 정확히 중복된 태그는 정리됩니다.
- `draft`: 선택적 boolean. `true`이면 웹사이트의 목록·상세·sitemap에서 제외됩니다. 생략하면 게시 상태입니다.
- `example`: 선택적 boolean. `true`이면 예제 글 안내를 표시합니다. 실제 글은 `false`로 두거나 생략합니다.
- 본문: 공백이 아닌 내용이 필요합니다.

잘못된 메타데이터는 빌드·글 읽기 시 오류를 냅니다. 초안 파일도 검증 대상입니다. `publishedAt`은 표시·정렬용이며 예약 발행 기능이 아닙니다. 미래 날짜라도 `draft: false`면 공개됩니다.

**공개 저장소 경고:** `draft: true`는 GitHub 원본이나 Git 변경 이력을 숨기지 않습니다. 공개해도 되는 초안만 커밋하고 비밀번호, 토큰, 서버 설정, 비공개 개인정보를 넣지 않습니다. 포트폴리오의 `noindex`도 비밀 자료 보관 기능이 아닙니다.

## 본문 형식

제목은 페이지에서 출력하므로 본문은 보통 `##`부터 시작합니다. 일반 Markdown과 GFM의 목록, 링크, 인용, 코드 블록, 표, 취소선 등을 사용할 수 있습니다.

원시 HTML은 렌더링하지 않습니다. MDX, 스크립트, iframe, 실행 가능한 사용자 컴포넌트는 지원하지 않습니다. 이미지를 링크할 때는 사용 권한·대체 텍스트·외부 요청에 따른 개인정보 노출을 확인합니다. 현재 미디어 업로드 관리 기능은 없습니다.

## 검색과 태그

- 검색은 제목·요약·태그·본문에 적용됩니다. 공백으로 나눈 검색어를 모두 포함해야 합니다.
- 검색어와 태그는 Unicode NFKC 정규화와 대소문자 정리를 거쳐 비교합니다.
- 태그는 정규화된 전체 값이 일치해야 하며 검색어와 동시에 적용됩니다.
- 조건은 `/computer?q=검색어&tag=태그` 형태의 URL에 남습니다.
- 현재 검색어는 최대 120자, 태그는 최대 80자까지 처리합니다.
- 글 목록은 날짜 내림차순, 같은 날짜는 slug 순으로 정렬됩니다.

태그 표기를 일관되게 유지하면 중복된 분류를 줄일 수 있습니다.

## 게시 전 확인

1. 목적에 맞는 `feature/` 브랜치에서 파일을 추가·수정합니다.
2. 메타데이터, 문장·링크, 이미지 사용 권한과 공개 범위를 확인합니다.
3. `npm run check`, `npm run build`, `npm run test:integration`을 차례로 실행합니다. 통합 검사는 앞서 만든 빌드가 필요합니다.
4. 로컬 서버에서 목록·검색·태그·상세 페이지를 확인합니다. 게시할 글만 `draft: false`로 전환합니다.
5. 최종 변경을 다시 검사하고 리뷰합니다. 커밋·push는 서버 배포와 별개이며, 배포는 별도 절차로 진행합니다.

초기 두 글은 기능 확인용 예제입니다. 실제 운영 콘텐츠로 바꾸거나 제거할 때 관련 테스트·smoke test가 예제 글을 전제로 하는지 함께 확인합니다.
