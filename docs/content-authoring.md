# Markdown 글 작성

기술 글은 `content/computer/`의 `.md` 파일로 관리합니다. 현재 웹 관리자 작성 화면은 없으며, 파일 수정 후 검사·새 빌드가 필요합니다.

## 파일과 메타데이터

파일명은 `my-first-post.md`처럼 영문 소문자·숫자와 단어 사이 하이픈을 사용합니다. 파일명이 `/computer/my-first-post`의 slug가 됩니다. 공백, 한글 파일명, 밑줄, 경로 구분자는 허용하지 않습니다.

```markdown
---
title: "첫 번째 기술 기록"
description: "목록에 보여 줄 짧은 요약입니다."
publishedAt: "2026-11-06"
tags: ["Linux", "운영"]
category: "server"
draft: true
example: false
---

## 기록할 내용

본문을 작성합니다.
```

- `title`, `description`: 비어 있지 않은 문자열, 필수.
- `publishedAt`: 따옴표로 감싼 유효한 `YYYY-MM-DD` 날짜, 필수.
- `tags`: 비어 있지 않은 문자열을 하나 이상 포함한 배열, 필수. 앞뒤 공백과 정확히 중복된 태그는 정리됩니다.
- `category`: 글의 분야를 나타내는 선택적 문자열. 새 글은 아래 여섯 ID 중 하나를 지정합니다. 기존 글에서 생략한 값은 추측하지 않으며 분야를 선택하지 않은 전체 목록과 검색 결과에서만 표시합니다.
- `draft`: 선택적 boolean. `true`이면 웹사이트의 목록·상세·sitemap에서 제외됩니다. 생략하면 게시 상태입니다.
- `example`: 선택적 boolean. `true`이면 예제 글 안내를 표시합니다. 실제 글은 `false`로 두거나 생략합니다.
- 본문: 공백이 아닌 내용이 필요합니다.

잘못된 메타데이터는 빌드·글 읽기 시 오류를 냅니다. 초안 파일도 검증 대상입니다. `publishedAt`은 표시·정렬용이며 예약 발행 기능이 아닙니다. 미래 날짜라도 `draft: false`면 공개됩니다.

### 분야 ID

| `category` 값 | 화면 표시 |
| --- | --- |
| `router` | Router |
| `switch` | Switch |
| `asa` | ASA |
| `server` | Server |
| `linux` | Linux |
| `windows-server` | Windows Server |

ID는 위의 영문 소문자 값과 정확히 일치해야 합니다. 알 수 없는 값이나 빈 문자열·`null`·배열을 명시하면 검증 오류가 발생합니다. 태그는 한 글에 여러 개를 붙일 수 있지만 분야는 하나만 지정합니다. 분야를 바꾸어도 글의 slug와 상세 주소는 유지됩니다.

**공개 저장소 경고:** `draft: true`는 GitHub 원본이나 Git 변경 이력을 숨기지 않습니다. 공개해도 되는 초안만 커밋하고 비밀번호, 토큰, 서버 설정, 비공개 개인정보를 넣지 않습니다. 포트폴리오의 `noindex`도 비밀 자료 보관 기능이 아닙니다.

## 본문 형식

제목은 페이지에서 출력하므로 본문은 보통 `##`부터 시작합니다. 일반 Markdown과 GFM의 목록, 링크, 인용, 코드 블록, 표, 취소선 등을 사용할 수 있습니다.

원시 HTML은 렌더링하지 않습니다. MDX, 스크립트, iframe, 실행 가능한 사용자 컴포넌트는 지원하지 않습니다. 이미지를 링크할 때는 사용 권한·대체 텍스트·외부 요청에 따른 개인정보 노출을 확인합니다. 현재 미디어 업로드 관리 기능은 없습니다.

### 기술별 인터랙티브 예제

다음 네 문서에 각자 대응하는 표식을 정확히 한 번 넣으면 해당 위치에 저장소의 예제 컴포넌트를 렌더링합니다.

| 파일 | 분야 | 표식 |
| --- | --- | --- |
| `vlan.md` | `switch` | `<!-- demo:vlan -->` |
| `routing.md` | `router` | `<!-- demo:routing -->` |
| `dns.md` | `server` | `<!-- demo:dns -->` |
| `dhcp.md` | `server` | `<!-- demo:dhcp -->` |

다른 글에 표식을 넣거나 다른 기술의 표식을 사용해도 컴포넌트를 실행하지 않습니다. 표식이 없거나 여러 개이면 일반 Markdown으로 렌더링합니다. 등록은 `src/lib/article-demos.ts`와 `src/components/computer/technology-demo.tsx`에서 관리합니다. 임의 HTML이나 MDX를 허용하는 기능이 아닙니다.

문서는 기술의 목적·구성·동작·운영 확인 사항·공식 출처를 담습니다. 실습에서는 실제 프로토콜의 일부를 단순화한 범위와 생략한 조건을 설명합니다. VLAN과 라우팅은 3D 장비 모형을 사용하며 DNS·DHCP는 실제 외부 패킷을 보내지 않습니다.

라우팅의 전체 분류는 `src/lib/routing-catalog.ts`에서 관리합니다. 항목에는 공식 출처와 분류를 넣고 대표 실습이 있는 경우에만 `lab`을 지정합니다. 메인 검색은 Markdown 본문·태그를 사용하므로 새 종류를 추가할 때 `routing.md`도 함께 갱신합니다. IPv6·멀티캐스트 등 설명만 제공하는 항목을 IPv4 실습의 완전한 구현처럼 표시하지 않습니다. 경로 선택 모델과 입력 검증은 `src/lib/routing-methods.ts`에 있습니다.

## 검색과 분야·태그

- 검색은 제목·요약·태그·본문에 적용됩니다. 공백으로 나눈 검색어를 모두 포함해야 합니다.
- 검색어와 태그는 Unicode NFKC 정규화와 대소문자 정리를 거쳐 비교합니다.
- 태그는 정규화된 전체 값이 일치해야 하며 검색어와 동시에 적용됩니다.
- 분야는 `category`의 정확한 ID로 선택합니다. 검색어·태그·분야는 교집합으로 적용됩니다. 예를 들어 `category=server&q=Linux&tag=운영`은 서버 분야의 글 중 검색어와 태그가 모두 맞는 글만 보여 줍니다.
- 조건은 `/computer?q=검색어&tag=태그&category=server` 형태의 URL에 남습니다. 각 조건을 비우면 해당 필터만 해제할 수 있습니다.
- 현재 검색어는 최대 120자, 태그는 최대 80자까지 처리합니다.
- 글 목록은 날짜 내림차순, 같은 날짜는 slug 순으로 정렬됩니다.

태그 표기를 일관되게 유지하면 중복된 분류를 줄일 수 있습니다.

## 일반 게시글 (POST)

홈 POST에 올릴 글은 `content/posts/`에 작성합니다. 첫 글을 쓸 때 폴더를 만들고 `weekend-note.md`처럼 영문 소문자·숫자·하이픈으로 파일명을 정합니다. 폴더가 없거나 공개된 글이 없으면 게시판은 비어 있습니다.

마크다운 머리말에 `title`과 따옴표로 감싼 `publishedAt` 날짜를 넣고 본문을 작성합니다. `category`에는 ‘공연 후기’처럼 분류명을 자유롭게 지정할 수 있으며 생략하면 ‘일반’으로 표시됩니다. `description`과 `tags`는 선택 사항입니다. `draft: true`인 글은 목록과 상세 화면에서 제외됩니다. 게시글은 날짜 내림차순으로, 같은 날짜의 글은 파일명 순으로 정렬됩니다.

## 게시 전 확인

1. 목적에 맞는 `feature/` 브랜치에서 파일을 추가·수정합니다.
2. 메타데이터, 문장·링크, 이미지 사용 권한과 공개 범위를 확인합니다.
3. `npm run check`, `npm run build`, `npm run test:integration`을 차례로 실행합니다. 통합 검사는 앞서 만든 빌드가 필요합니다.
4. 로컬 서버에서 목록·검색·태그·상세 페이지를 확인합니다. 게시할 글만 `draft: false`로 전환합니다.
5. 최종 변경을 다시 검사하고 리뷰합니다. 커밋·push는 서버 배포와 별개이며, 배포는 별도 절차로 진행합니다.

초기 두 글은 기능 확인용 예제입니다. 실제 운영 콘텐츠로 바꾸거나 제거할 때 관련 테스트·smoke test가 예제 글을 전제로 하는지 함께 확인합니다.
